# 01 — 产品需求与玩法交互设计 (PRD & Gameplay Specification)

> **状态**: 活跃规范（Phase 1 执政官模式为核心交付，Phase 4 独立基地模式为远期规划）

---

## 1. 项目愿景与核心目标

为《亿万僵尸》（They Are Billions）打造原汁原味、零服务器门槛的 **2~3 人 Steam P2P 合作联机 Mod**：
- **无需公网 IP 或自建专用服务器**：依托 Steamworks P2P（`SteamMatchmaking` Lobby + `SteamNetworking`），支持好友直接创建房间、邀请加入，并提供本机 TCP Loopback（`127.0.0.1:27099`）用于无双账号测试。
- **双阶段演进路线**：
  1. **模式一（当前核心交付）：执政官模式（Archon Mode / 共控一族）** —— 2~3 名玩家共同执掌同一个人类帝国殖民地，分工负责运营建造、多线清图、暴兵与尸潮防守。
  2. **模式二（Phase 4 远期拓展）：独立基地模式（Independent Bases Mode）** —— 每名玩家拥有独立的指挥中心（Command Center）、独立经济资源池与单位控制权，协同防守同一张地图。

---

## 2. 模式一：执政官模式（Archon Mode）交互设计

在执政官模式下，游戏底层仍然只有 1 个人类阵营（`ZXTeamType.Player`），但允许 2~3 名玩家以**完全独立的视角与交互上下文**同时操作。

### 2.1 玩家身份与色彩标识
房间内支持最多 3 名玩家，固定分配高辨识度主题色（见 `AllyOverlayRenderer.GetPlayerColor`）：
- **Player 1 (Host / 房主)**：皇家蓝（`Color.DodgerBlue` / `#1E90FF`）
- **Player 2 (Client 1)**：翡翠绿（`Color.SpringGreen` / `#00FF7F`）
- **Player 3 (Client 2)**：琥珀橙（`Color.Orange` / `#FFA500`）

### 2.2 本地独立状态 vs 全局共享状态

| 维度 | 状态归属 | 交互表现说明 | 实现状态 |
| :--- | :--- | :--- | :-: |
| **摄像机视野 (Camera)** | **本地独立** | 每名玩家自由平移、缩放各自的屏幕，互不拉扯视角。 | ✅ |
| **单位/建筑框选 (Selection)** | **本地独立** | 各自下方属性栏与右下方命令面板显示自己选中的对象，绝不互相顶掉。 | ✅ |
| **编队快捷键 (Ctrl+1~9)** | **本地独立** | 每名玩家的编队保存在各自客户端本地。 | ✅ |
| **建筑建造预览 (Build Ghost)** | **本地独立** | 拉电塔/木墙网格预览时不影响队友；左键确认落地瞬间再全局同步生成。 | ✅ |
| **资源与电力/食物池** | **全局共享** | 金/木/石/铁/油、电力、食物、工人全员共享，实时统一扣减。 | ✅ |
| **单位与建筑控制权** | **全局共享** | 任何人都可以选中并下达移动/攻击/技能指令，按统一 `TargetSimTick` 顺序执行。 | ✅ |
| **战争迷雾 (Fog of War)** | **全局共享** | 共享全部人类建筑与单位的视野层。 | ✅ |

### 2.3 时间控制（空格暂停、倍速与 3 秒倒计时）
《亿万僵尸》重度依赖“暂停建房、暂停拉兵”，联机下的暂停体验要求如下：
1. **暂停触发与横幅提示**：
   - 任意玩家按下 `Space`（或点击暂停快捷键）时，发送 `NetCommandType.SetPaused` 至 `CoopSessionManager` 同步至全员。
   - 屏幕顶部中央显示横幅提示：`Player <ID> Paused Game`（使用 `durationMs=0` 确保冻结帧下文字立即 100% 不透明显示）。
   - 请求恢复运行时，先在屏幕顶居中显示 **`Resume in 3... 2... 1...`** 悬浮倒计时框，倒计时结束由 Host 统一发出 `SetPaused(false)` 在同 Tick 恢复世界模拟。
2. **暂停期间的实时微操**：
   - 暂停期间（`PausedBySession == true`）游戏逻辑帧 `SimTick` 与 `GameTime` **严格冻结**，但主渲染帧与网络心跳照常运行。
   - 玩家在暂停期间的放置建筑、移动/攻击/取消、兵营排队等操作，会**即时广播并执行渲染**（不等待解冻），与单机空格微操体验一致。
3. **游戏倍速切换**：
   - 支持 `+` / `-` 快捷键或指令同步调节游戏倍速（`SetGameSpeed`，0..20）。

### 2.4 市长选举（Mayor Selection）同步机制
当殖民地人口达到阈值（30 / 100 / 200 / 600 / 1200）触发市长选举弹窗（`ZXGame.#=zcITiOSD6YNmD()`）：
- 由于确定性随机数已同步，全员同时弹出相同候选市长。
- 当前已实现**按 `MayorId` 确定性同步应用**：拦截市长应用（`MayorSyncPatch`），发送携带 `MayorId` 的 `NetCommandType.MayorVoteOrSelect`，各端直接按 ID 从 `ZXMayor.#=zoTuFkHI=` 查找应用，不依赖两端重抽样。
- **进阶规划**：支持客机点选意向高亮（`"[玩家2 推荐]"`）+ 房主拍板模式。

### 2.5 盟友态势感知（Co-op UX）
1. **小地图队友视野框**（✅ 已落地）：在右下角 `OMiniMap` 上除本地白框外，实时绘制每位队友代表色（2px 像素边框）的当前相机视野矩形框。
2. **地面队友光标与建造预览提示**（🔄 光标网络广播已就绪，地面绘制持续完善）：通过 20Hz Unreliable 通道广播本地鼠标世界坐标与视野范围。
3. **小地图与地面信号打点（Tactical Ping）**（✅ 已实现）：支持发送 `PacketType.TacticalPing`，调用 `OMiniMap.#=zvr$ku1Q=` 播放雷达闪烁波纹动画。

## 3. 大厅、开局与热同步流程（Lobby & Session Flow）

### 3.1 主菜单入口与传统 RTS 等候房间
1. 在主菜单 `TMenuCategory.Main` 注入 **`CO-OP MULTIPLAYER`** 按钮，并随游戏生命周期挂载全局 Steam 邀请监听（`GameLobbyJoinRequested_t` 与 `+connect_lobby` 启动参数）。
2. 点击打开基于原版 `ZXWindow(BigWindow)` 与 `ZXButtonSteam` 构建的传统 RTS 等候房间（`CoopLobbyWindow`），包含双态视图：
   - **入口视图（未加入房间）**：左侧提供 **创建 Steam 好友房间**（`SteamMatchmaking.CreateLobby`）与 **创建本地测试房间**（`127.0.0.1:27099`）；右侧通过非侵入式 `LobbyProbe`/`LobbyProbeAck` 自动探测本地已有主机并展示房主名、人数与阶段，探测就绪后方可 **加入本地房间**。
   - **等候房间视图（已连接）**：左侧展示 3 个执政官彩色席位（`P1` 蓝、`P2` 绿、`P3` 橙）与 `★ 房主` / `✓ 已准备` / `○ 未准备` 状态徽章；右侧客机切换 **进入准备状态 / 取消准备**（支持中途加入断线重连）；**至少 1 名客机入房且全员已准备** 后，房主方可选择 **从存档加载...**、**新建生存游戏...** 或 **自定义地图...**（直接复用单人模式原生界面，取消菜单会自动重开等候大厅）。
3. **动态随机换图与退局回大厅（方案 A）**：非固定测试模式下每次建房或新开局都会生成动态随机 `SyncSeed` 下发同步；房主或对局通过 `ReturnToMainMenu` 返回主菜单时，保留双端网络连接并重置客机准备状态，自动回到等候房间。

### 3.2 零地图生成差异的“内存存档流直传”开局流程
1. **房主导出快照**：房主进入关卡完成（`OnLevelLoadComplete`）后，在浅调用栈顶层调用 `WriteSaveFile` 导出临时 `.zxsav` + `.zxcheck`（统一文件名 `coop_host_snapshot.zxsav/.zxcheck`），切分为 `32 KB` `SnapshotChunk` 广播。
2. **客机热加载**：客机按分片索引乱序安全缓冲重组并落盘，通过 `PrepareForProgrammaticLoad()` 清理状态并推进淡入动画，调用 `LoadSaveFileAndEnter` 进入完全一致的关卡状态，随后发送 `SnapshotLoadedAck` 对齐基准 Tick。

### 3.3 周期状态校验与自动热同步（Auto-Resync）
- 每 60 逻辑帧（2 秒）计算 `StateHasher` v2 校验和并由客机上报房主比对。
- 若检测到任何偏差（如原生 Chipmunk C++ 物理求解器在极密集尸群下偶发的 `1e-4` 级别数值漂移），房主自动触发 `DesyncDetectedAlert` + 重传最新内存快照，实测约 **3 秒内**完成无缝重对齐并恢复锁步推进，避免长局报废。

## 4. 模式二（Phase 4 远期规划）：独立基地模式设计概要

在执政官模式全流程稳定后，按如下架构拓展“各自为战合作守图”：
1. **多基地生成**：房主开局在安全对称空地额外生成第 2、3 座 `CommandCenter` 及初始单位。
2. **Mod 层虚拟阵营账本**：维护 `Dictionary<ulong, byte> EntityOwnerMap` 与三套独立 `PlayerResourcePool`，Hook 顶栏资源 UI 按本地玩家渲染。
3. **权限隔离与尸潮分流**：默认仅允许控制己方单位/建筑（可选盟友代管与资源交易），并按比例分流进攻尸潮目标点。
